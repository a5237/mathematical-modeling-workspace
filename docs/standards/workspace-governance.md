# 数学建模工作区 Agent 强制规范

> 适用范围：数学建模项目的文件路由、数据保护、环境记录、代码运行、产物保存、证据追溯、复现、审校和交付。
>
> 不适用范围：论文正文的章节写法、摘要表达、公式与表格排版由 `docs/standards/paper-writing.md` 管理；图片与科研可视化由 `docs/standards/paper-figures.md` 管理。
>
> 核心原则：**论文保持学术表达，工程信息留在工作区；所有结果可运行、可定位、可核验、可交付。**

本文只定义工程治理门禁。目录职责、命名、证据字段、论文内容、学习流程、官方规则和质量评分的唯一权威见 `docs/README.md`；本文引用这些规则时不重新定义其阈值。

---

## 0. 两套规范的边界

工作区必须保存复现所需的详细信息，但不得自动把它们写入论文正文。

| 信息 | 工作区要求 | 论文中的默认处理 |
|---|---|---|
| 操作系统、软件和库版本 | 记录并可锁定 | 不写；直接影响结果时例外 |
| 安装方法、运行入口、命令行 | 必须有复现说明 | 不写入正文 |
| 输入输出文件、目录和日志 | 明确映射并保存 | 只引用必要结果，不写路径 |
| 随机种子 | 随机过程必须固定并记录 | 仅在影响科学判断时说明 |
| 运行时间、内存、复杂度 | 规模或性能相关时记录 | 仅在题目或方法选择需要时讨论 |
| 数据审计和处理明细 | 完整保存 | 只写影响模型与结论的规则 |
| 证据索引和文献台账 | 必须维护 | 不作为论文内部章节 |
| 对成果有实质影响的 AI 使用 | 按事件登记 | 只按官方规定标注和引用 |

若不确定某条信息应放哪里，先问：**评审理解模型与结论是否必须知道？** 若否，放工作区而非正文。

## 1. 优先级与必读文件

发生冲突时按以下顺序执行：

1. 比赛当届官方规则与用户当前明确要求；
2. 本工作区规范；
3. `docs/standards/naming.md`；
4. `docs/architecture/workspace-layout.md`；
5. 项目内 `00-admin/` 的明确约定；
6. 工具默认行为。

---

## 2. 项目路由与权威来源

### 2.1 文件路由（`WG-ROUTE-001`）

仓库级和项目级文件由 Agent 按 `docs/architecture/workspace-layout.md` 路由，稳定命名按 `docs/standards/naming.md` 执行。普通目录组织、文件命名、根目录整洁和 `q01` 等稳定标识属于 Agent 工程责任，不要求 Python 逐项证明；只有路径错误会破坏运行、解析、追溯或正式提交时才由机器阻断。

治理层只追加三项不可绕过的硬约束：原始数据执行 `WG-DATA-001`，证据执行 `WG-EVID-001`，临时产物不得成为唯一证据或交付物。布局工具只拦截明显的缓存/生成污染、批量项目产物散落和会造成冲突的废弃结构，不冻结仓库或项目目录树。

### 2.2 一个权威来源

- 同一数据、参数、指标、图表和论文不得维护多个相互竞争的“最终版”。
- 原始数据、机器结果、论文主源和发布文件分别以项目目录树中登记的对应产物为权威；具体位置执行 `docs/architecture/workspace-layout.md`，版本命名执行 `docs/standards/naming.md`。

---

## 3. 项目初始化与问题清单

新需求先进入 `workspace/inbox/`：保存题目要求、用户说明和原始附件。Agent 明确比赛、年份和题号后，优先使用生产 Skill 的初始化脚本在 `workspace/projects/` 创建推荐项目骨架，再按职责把题面与附件分类到 `01-problem/` 和 `02-data/raw/`，更新问题清单并清空对应 inbox，随后触发 `WG-MODEL-001`、数据审计、证据登记、`PWL-GATE-001` 和论文生产流程。

初始化骨架是可靠默认值，不是审计 schema。项目可根据题目增加、拆分或重构 `experiments/`、`benchmarks/`、`simulations/` 等目录，只要权威数据、模型、结果、证据和交付关系仍清楚且可复现。

在建模前，`01-problem/problem-checklist.md` 至少记录：

- 题目版本、附件清单和文件校验信息；
- 每个子问题的输入、输出、约束和评价口径；
- 各问依赖关系与必须生成的论文/附件结果；
- 数据缺口、外部资料需求和暂定假设；
- 官方格式、AI 使用、匿名性和提交要求的核对日期。

需求发生变化时更新清单，不依靠聊天记忆或临时笔记作为唯一依据。

项目还必须维护：

- `03-models/model-selection.md`：按 `WG-MODEL-001` 完成模型与算法选择记录；
- `00-admin/pre-writing-learning.md`：按 `docs/guides/pre-writing-learning.md` 的 `PWL-GATE-001` 完成写作前学习记录。

两项记录必须分别通过 `WG-MODEL-001` 和 `PWL-GATE-001` 后才能进入对应阶段；状态值、内容充分性和失效条件以各自权威规则为准。

## 4. 原始数据与处理数据

### 4.1 原始数据只读（`WG-DATA-001`）

- 不得覆盖、清洗后写回或手工修正 `02-data/raw/` 中的文件。
- 保留原始文件名、来源、接收日期、大小和必要校验值。
- 需要转换格式时，把派生文件写入 `02-data/processed/`，并保留可重复执行的转换程序。

### 4.2 数据审计

项目内部必须记录：

- 字段、类型、单位、样本量、时间和空间范围；
- 主键、重复、缺失、异常、非法编码和数量级；
- 处理规则、处理前后样本量和受影响对象；
- 训练/验证/测试或时间切分；
- 时间、对象、空间和目标泄漏风险；
- 每一步处理对应的代码和输出文件。

任何手工调整关键数据的行为均禁止。确需人工标注时，必须保留原值、标注规则、标注者匿名编号和变更记录。

## 5. 环境、版本与完整复现

### 5.1 环境记录

项目应在 `00-admin/` 或项目根部的明确复现文件中记录：

- 操作系统和处理器架构；
- Python、MATLAB、R、求解器或其它主要软件版本；
- 直接影响运行的库版本及锁定文件；
- 外部可执行程序、许可证或系统依赖；
- 字体、LaTeX 引擎或文档转换工具等发布依赖。

不得把整台机器的无关软件清单写入记录。版本记录服务于复现，不服务于堆砌。

### 5.2 复现说明

每个正式项目必须有一份权威复现说明，至少包含：

- 环境准备或依赖安装方式；
- 主运行入口和按子问题运行的入口；
- 相对路径下的输入、输出和配置映射；
- 完整计算顺序；
- 预计运行时间和主要资源需求；
- 随机种子或确定性设置；
- 成功标志、输出文件和常见失败处理；
- 论文编译、渲染和审校命令。

命令必须在当前项目环境中实际执行过。禁止写未验证的“理论上可运行”说明。

### 5.3 路径与工作区身份卫生

- 程序只使用相对路径、项目根路径解析或显式配置，不得硬编码个人绝对路径。
- 未进入交付包的日志、Notebook 输出和缓存不得出现用户名、学校或其它身份信息，并按第 10.2 节排除在交付之外；一旦纳入支撑材料，改按 `docs/standards/paper-writing.md` 第 15.3 节检查。

## 6. 代码、参数与计算过程

### 6.1 算法选择与资源库优先级（`WG-MODEL-001`）

- 建立模型和编写代码前，必须先从 `resources/algorithm-library/index.md` 定位相关类别，并只读取与当前子问题匹配的算法说明。
- 资源库中存在满足本题目标、假设、数据、约束和验证要求的算法时，主模型和代码实现应优先采用或基于该算法。
- 只有资源库未覆盖、适用条件不满足，或库外方法在本题评价指标上具有可说明、可验证的优势时，才可采用库外算法；原因、来源、比较方式和验证方案必须写入 `03-models/model-selection.md`。
- 资源库是首选候选与实现参考，不是无需判断的权威答案。所有公式、参数、依赖、代码示例和文献条目必须结合题目复核；代码必须项目化改写并真实运行，文献必须另行核验登记。
- 每道子问题最多采用两个独立的主模型体系；同一物理机制的不同精度展开按一个模型族计数。基准模型、消融和验证对照不计入主模型数量，但不得借此堆砌主模型。

### 6.2 代码要求

- 所有论文数值、图表和结论必须由已保存代码、明确推导或可核验资料产生。
- 随机过程固定随机种子；并行、GPU 或非确定性算法应记录确定性限制。
- 关键参数写入配置文件或集中定义，不散落在多个脚本中。
- 代码不得依赖未登记的手工步骤、临时路径或交互式状态。
- Notebook 可用于探索；进入论文的最终结果必须沉淀为可重复运行的脚本或明确的稳定执行单元。
- 不保存与项目无关的测试代码、第三方库源码和大量无意义调试输出。

### 6.3 计算检查

每个子问题按适用情况执行并保存：

- 单位、维度、范围和边界检查；
- 约束满足性、可行性和目标值复核；
- 基准模型、样例或人工可核对的小规模算例；
- 数据泄漏、标签穿越或未来信息检查；
- 收敛、残差、守恒、网格无关性、重复抽样或稳定性检查；
- 敏感性、误差、稳健性或消融运行。

不得声称完成某项检查而没有对应程序输出、表格、指标或日志。

### 6.4 性能与复杂度

- 运行时间、内存、并行设置和规模上限只在会影响复现、求解可行性或方法选择时记录。
- 不强制为每个算法撰写时间复杂度和空间复杂度。
- 如果论文确需讨论复杂度或规模可行性，必须由实际规模、算法结构或测量数据支撑，而不是套用通用大 O 结论。

## 7. 结果产物与证据链

### 7.1 稳定产物

- 关键表格保存为 CSV/XLSX 等机器可读格式。
- 关键指标保存为 JSON/YAML/CSV 等结构化格式。
- 图片产物必须按 `docs/standards/paper-figures.md` 的 `PW-FIG-001` 生成、导出和审校；本规范只负责其稳定路由与复现。
- 控制台临时输出不得作为论文数值的唯一来源。
- 每次正式运行保存参数、时间、状态和必要日志；失败日志与正式结果区分。

### 7.2 证据索引（`WG-EVID-001`）

所有重要数值和事实主张必须按 `docs/standards/evidence-contract.md` 登记到 `05-evidence/evidence-index.csv`，并在写入论文前达到契约要求的状态。本文只规定证据目录和生命周期，不另行维护字段、状态值或文献核验定义。

### 7.3 文献台账

文献检索与核验记录执行 `docs/standards/evidence-contract.md`；论文中的文献数量、组成和引用表达执行 `docs/standards/paper-writing.md`。资源库书目只能作为检索线索。

### 7.4 AI 使用台账（`WG-AI-001`）

`05-evidence/ai-tool-log.md` 按“实质影响事件”登记：

- 主要使用的 AI 工具、模型/版本、机构和日期；
- 主要使用阶段与目的；
- 对模型、代码、论文或交付有实质影响的典型提示方式或方法；
- 主要采纳内容及其对应位置；
- 人工修改；
- 人工验证方式与证据。

普通问答、每个小 prompt、措辞微调、无实质影响的交互和完整聊天流水账不必记录。按 `docs/standards/cumcm-current-rules.md` 从台账生成当届要求的声明和详情文件；不得在比赛结束时凭记忆补写 material AI usage。

## 8. 论文生产与同步

- 论文写作前必须通过 `docs/guides/pre-writing-learning.md` 的 `PWL-GATE-001`；本文不重复学习数量、记录字段和失效条件。
- 论文只能引用满足 `WG-EVID-001` 的数值和事实主张。
- `06-paper/figures|tables/` 只保存论文实际引用的副本，并能追溯到 `04-results/` 权威产物。
- 论文中的全部图片必须通过 `PW-FIG-001`。
- 论文中若出现人工复制的数值，必须与机器可读来源进行自动或人工双重核对。
- 开发阶段按需要运行和验证。进入 Release Candidate 后冻结主要代码、数据处理和参数，由 Final Audit 在 clean directory 或等效干净环境中完整执行正式入口一次；该次强复现替代此前完全相同的发布前全量重跑。

---

## 9. 编译、渲染与发布检查（`WG-RELEASE-001`）

生产阶段只负责从权威论文源持续生成可检查 PDF，不维护 final hash 或完整发布状态。进入 Release Candidate 后，由独立 Final Audit 一次完成：

1. clean reproduction 与关键输出核对；
2. 从权威论文源生成拟交付 PDF；
3. 逐页渲染，并在同一次检查中核对分页、表格、公式、字体、版面和全部图片；
4. 按 `OFFICIAL-CUMCM-001` 检查页面、尺寸、文件大小、匿名性和提交材料；
5. 检查文档属性、图片元数据、批注、修订和隐藏内容；
6. 把哈希、证据、发现项、竞争力评分和唯一发布结论保存到 `07-review/final-audit.md`。

Draft、Release Candidate 和 Final 的失效与局部复查规则执行 `docs/standards/paper-quality-audit.md`。只核对源文件、不检查最终渲染结果和字体属性，仍视为未完成发布检查。

## 10. 独立审校与交付

### 10.1 写作与审校分离

- 写作者不得把自己的完成声明当作审校证据。
- 发布前运行 `.codex/skills/cumcm-paper-audit/` 的独立审校流程。
- 审校只维护 `07-review/final-audit.md` 一份最终报告，并执行 `PQA-REPORT-001`。修复应回到权威数据、代码或论文源，不在审校目录悄悄改成品。
- 发布必须通过 `PQA-RELEASE-001`。
- 国奖竞争力评分用于评价和修改建议，不决定普通发布状态；无论得分多高都不得声称官方获奖保证。

### 10.2 交付包

`08-delivery/` 只保留当届要求提交的成品和 `file-list.md`。交付前检查：

- 论文、附录和支撑材料内容一致；
- 源程序完整可运行，支撑材料列表与压缩包一致；
- 压缩格式、文件大小和命名符合当届通知；
- 无原始赛题数据的重复提交，除非官方明确要求；
- 无缓存、临时文件、失败日志、个人路径、身份信息或无关草稿；
- AI 使用详情、未使用声明或其它官方声明齐全。

---

## 11. 严格禁止事项

控制编号不再自动等同于机器阻断项。普通路由、命名、过程整洁和 Reviewer judgment 由 Agent 依据规范执行；机器只阻断高风险、客观且稳定的问题。原始数据保护、模型选择、证据真实性、写作前学习、核心验证、最终图片真实性、官方规则、匿名性、复现和交付硬错误仍不得绕过，也不得以聊天记录、作者声明、未保存输出或审校目录中的成品修改替代权威证据和源文件修复。

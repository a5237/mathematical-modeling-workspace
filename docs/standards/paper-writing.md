# 数学建模论文写作 Agent 强制规范

> 适用范围：全国大学生数学建模竞赛（CUMCM）及同类本科生数学建模竞赛论文的分析表达、模型论证、结果叙事、表格、学术引用、通用排版和论文附录。图片与科研可视化执行 `docs/standards/paper-figures.md` 的 `PW-FIG-001`。
>
> 核心原则：**论文质量不得因规范重构而降级；工程职责可以迁移，学术论证、写作细则和排版门禁必须完整保留。**
>
> 边界说明：项目目录、环境安装、软件与库版本、运行入口、命令行、输入输出路径、日志、证据台账、AI 交互台账和完整复现手册由 `docs/standards/workspace-governance.md` 管理，原则上不写入论文正文。凡直接影响模型定义、求解过程或结论可信度的科学设置，仍必须在论文中说明。

---

## 0. 规范用语与执行级别

- **必须 / 不得**：硬性要求，未满足不得发布。
- **应 / 原则上**：默认执行；确因题型不适用时，必须采用等效论证并说明理由。
- **宜 / 推荐**：质量提升项，应结合题目选择。
- **可**：允许但不强制。

不得以“内容自适应”为由删除必要的模型、求解、结果、验证、图表、文献或排版要求；也不得把“推荐”机械升级为所有题目必须采用的固定模型或固定图表。

## 1. 规则优先级与现行官方基线

发生冲突时按以下顺序执行：

1. 比赛当届官方规则、论文格式规范、AI 工具使用规定和赛区补充要求；
2. 用户在当前任务中的明确要求；
3. 赛题对输出内容和文件的要求；
4. 本规范；
5. 已复制到项目 `06-paper/main.tex` 的 `resources/templates/cumcm-paper-framework.tex` 正式写作框架；
6. Agent 默认习惯。

年度官方规则、核对日期、生效边界和官方链接只以 `docs/standards/cumcm-current-rules.md` 的 `OFFICIAL-CUMCM-001` 为准。正式参赛前必须重新打开全国组委会官网，不得仅凭本规范作最终合规判断。

### 1.1 官方规则与工作区增补

`OFFICIAL-CUMCM-001` 规定当届官方底线；官方未统一规定的字体、字号、行距、颜色及内部质量门禁由本规范和 `docs/standards/paper-quality-audit.md` 增补。工作区增补不得冒充全国组委会统一规定，官方或赛区要求更严格时从其规定。

### 1.2 写作启动门禁

论文正文和摘要写作前必须通过 `docs/guides/pre-writing-learning.md` 的 `PWL-GATE-001`，并确认 `WG-MODEL-001` 与 `WG-EVID-001` 已满足当前写作所需状态。学习数量、记录字段、模型选择和证据状态只以对应权威文件为准。

### 1.3 唯一写作框架与无状态交付

1. 每次启动正式论文写作前，必须先将 `resources/templates/cumcm-paper-framework.tex` 复制为项目 `06-paper/main.tex`，并以该文件作为唯一权威论文源；初始化脚本已经完成复制时，不得再次覆盖。
2. 后续写作、排版、修订和编译只修改 `06-paper/main.tex` 及其实际引用的图表、文献资源，不得另建平行论文源、自由稿或替代章节框架。
3. 每次修改后的论文源和生成文件必须保持 **Stateless Deliverable（无状态交付）**：内容本身可直接进入审校与交付，不设置“修改说明”“版本变化”“补丁摘要”“修改理由”“写作过程”等章节或段落，也不夹带面向修改过程的解释。必要的工程与审校记录分别保存在 `00-admin/` 和 `07-review/`，不得进入论文。

## 2. 通用高质量写作原则

### 2.1 全文主线与证据闭环

论文必须形成清晰主线：

```text
题目要求
→ 问题抽象与任务拆解
→ 数据理解或机理分析
→ 变量、指标与模型建立
→ 算法或方法求解
→ 主要结果
→ 结果解释与验证
→ 最终方案、评价与推广
```

每个子问题都必须形成“提出—数学化—求解—回答—检验”的闭环。不得出现只有模型没有结果、只有结果没有推导、只有图表没有解释、只有程序没有数学表达的断裂章节。

### 2.2 模型适度与内容自适应

1. 模型复杂度由题目决定，不以模型数量或算法名称评价质量。
2. 简单模型足以解决问题时，应优先采用结构清楚、可解释、可验证的方法。
3. 使用复杂模型时，必须说明简单方法为何不足、复杂模型新增了什么能力、是否获得可核验增益。
4. 不同题型采用不同数学表达；非优化问题不得强行设置目标函数和 `s.t.`。
5. 不得照搬范文中的模型、变量、公式、图表和章节细节。
6. 题型不适合某项图表或验证时，应使用推导、证明、算例、边界检查或其它等效证据，不得直接删去论证职责。

### 2.3 物理、工程与连续系统问题

处理物理机理、工程设计、微分方程、连续介质、传热传质或数值模拟问题时，应：

1. 从守恒定律、物理定律、几何关系或可靠机理出发，不直接堆叠经验公式；
2. 说明真实场景如何被降维、分层、理想化及忽略哪些次要因素；
3. 完整列出控制方程、初始条件、边界条件、界面条件、耦合条件和定义域；
4. 不能解析求解时，比较候选数值方法的稳定性、精度和适用条件；
5. 写清必要的离散过程、网格或步长、矩阵关系和求解方法，不能只写“调用软件求解”；
6. 使用实测值、基准解、残差、收敛性、守恒量、网格无关性或误差指标进行量化验证；
7. 对关键参数、边界条件和最优方案进行灵敏度、扰动或最优性检查；
8. 在模型评价中回扣简化假设、数值误差、计算可行性和适用边界。

图片证据的表达强度执行 `PW-FIG-001`，并必须与 `PW-VAL-001` 要求的数值指标或明确判据共同支撑结论。

### 2.4 数据驱动、评价、预测与决策问题

处理统计、评价、分类、预测、机器学习或数据驱动决策问题时，应：

1. 先完成数据审计，再进行特征构造、训练或优化；
2. 按业务含义、数学作用或因果位置解释特征，不把大量原始字段直接堆入模型；
3. 指标必须说明方向性、计算方式、实际含义及其与题目目标的关系；
4. 原则上设置可解释的基准模型，再说明复杂模型相对基准新增的能力和实际增益；
5. 使用与任务匹配的数据划分和评价指标，不得只报告训练集表现；
6. 类别不平衡、时间依赖、空间相关或对象重复时，采用相应验证和防泄漏方案；
7. 集成模型说明基模型、融合方式、权重或投票依据，以及相对单模型的增益；
8. 预测概率、评分或聚类标签必须继续转化为题目要求的排序、分配、额度、类别、路径、策略或方案；
9. 结果表必须直接回答题目，不能让读者自行从中间概率或原始输出推导最终答案；
10. 正文保留核心模型、关键比较和主要结果，超长明细放入附录。

高准确率、高拟合度或高评价指标不能单独证明模型优秀，必须同时说明数据划分、评价口径、泄漏检查、稳健性和适用范围。

### 2.5 多子问题、情景变化与模型继承

当各子问题具有递进关系时，应：

1. 在问题分析中说明各问依赖关系和整体技术路线；
2. 明确后续问题继承了哪些数据、变量、模型、参数和结论；
3. 单独列出新增或修改的目标、约束、参数、情景和输出；
4. 不重复粘贴完全不变的公式，也不得只写“同前”而省略关键修改；
5. 情景变化形成“影响因素—参数或指标变化—模型调整—结果变化”的逻辑链；
6. 每一问都给出独立、可识别的最终答案和验证材料。

### 2.6 真实性、可核验性与全文一致

- 不得编造原始数据、参数来源、计算结果、模型性能、软件输出、文献或检验结论。
- 所有具体数值必须来自题目数据、可核验资料、明确推导或真实运行的程序输出。
- 缺少必要数据时，必须说明缺口，并采用有依据的假设、符号化表达、区间结果或条件性结论。
- 摘要、正文、图表、附录和支撑材料中的模型名称、数值、单位、对象编号和舍入必须一致。
- 每个英文缩写首次出现时使用“中文名称（英文全称，英文缩写）”；摘要与正文分别视为独立文本，首次出现均需解释。
- 论文图片的职责边界、图型选择、生成与视觉审校统一执行 `PW-FIG-001`。

### 3.1 正文字数门禁（`PW-LEN-001`）

正文叙述性内容不得少于 **5000 字**。统计范围为“问题重述”起至“模型的评价与推广”结束的可读正文文字；摘要、关键词、参考文献、附录、代码、纯公式符号以及图表内部文字不计入。中文汉字、独立英文单词和数字串均按 1 字计。不得用无关背景、重复论述或空泛文字凑足篇幅；当届官方或赛区要求更严格时，从其规定。

### 3.2 结构适配边界

- 一级章节的名称、顺序和职责固定，不得自行新增、删除、改名、合并或调序；只有比赛官方要求或用户明确要求与本结构冲突时才可调整，并必须保留全部章节职责。
- 子问题数量按题目实际增减；同一问使用多个模型时，只可在对应分问的模型建立或求解下增设确有内容依据的更低级标题，不得据此新增一级章节或与固定章节并列的独立部分。
- 不得把第二章“问题分析”与第五章“模型建立”合并。
- 第五章每问的“建模准备”必须保留，负责就近给出模型建立前必需的坐标、几何判定、数据变换、指标定义、机理简化、继承关系或预备公式；不得再使用“模型分析”作为该小节名称，也不得直接复制第二章。
- 每个可独立命名的主模型、局部模型或模型组件都必须在相应内容左上方设置“模型名称——作用”的加粗左对齐小标题；必要图示的触发、类型、位置和质量执行 `PW-FIG-001`。
- 数据预处理、模型检验、敏感性分析或方案说明内容较多时，只可在相应固定章节或分问内设置更低级小节，不得另起一级部分或打乱论文主线。
- 摘要页、目录和官方分页执行 `OFFICIAL-CUMCM-001`；本工作区另要求每个独立附录或附件单独新起一页。

## 4. 页面、字体、字号与段落（`PW-FMT-001`）

### 4.1 页面设置

1. 有官方模板时，严格服从官方纸张、方向、页边距、页眉页脚和页码要求。
2. 官方未规定时使用 A4、纵向、单栏，页边距不小于官方要求。
3. 不得为把摘要塞入一页而缩小到不可读字号、压缩行距或缩窄页边距。
4. 宽表确需横向时，可对单独页面分节设置横向，其余页面保持纵向。
5. `resources/templates/` 中若存在培训展示型 Word 框架，其横向页面、左右文本框、彩色提示、黄色高亮和虚线边框不自动继承为正式论文版式。
6. 正式稿必须删除模板提示、批注、修订、占位符和教学文字。
7. 官方未另行规定时，不设装饰性页眉；页码使用阿拉伯数字，置于页脚居中，并从摘要页连续编号。
8. 正文、标题、表格和公式说明默认使用黑色；论文图片的颜色与冗余编码执行 `PW-FIG-001`。

### 4.2 字体硬要求

1. 全部中文字符统一使用宋体，包括题目、标题、正文、摘要、关键词、图题、表题、表内文字、页眉页脚、参考文献和附录。
2. 中文标题强调时使用加粗宋体，不改用黑体、楷体、仿宋或微软雅黑。
3. 全部英文、英文缩写、拉丁字符、阿拉伯数字、希腊字母和数学符号统一使用 Times New Roman 或兼容的 Times 系列数学字体。
4. 数学变量和参数使用 Times 系列斜体；函数名、单位和说明性符号使用正体。
5. 图表内部执行同一中西文字体规则，不保留绘图软件默认字体。
6. 代码块可使用等宽字体，代码外标题和说明仍执行宋体/Times 规则。
7. 不得通过在交付包中嵌入或分发字体文件规避字体要求。
8. 论文题目、“摘要”、全部编号标题、建模准备标题、模型或算法功能性小标题、模型评价分项标题和附录标题必须加粗；不得出现同级标题有的加粗、有的不加粗。

### 4.3 推荐字号与段落

官方或赛区未规定时采用以下默认值：

| 内容 | 字体与字号 | 对齐与段落 |
|---|---|---|
| 论文题目 | 宋体，三号（16 pt），加粗 | 居中，尽量一行 |
| “摘要”标题 | 宋体，四号（14 pt），加粗 | 居中 |
| 摘要正文 | 宋体，小四 | 两端对齐，首行缩进 2 字符 |
| 关键词 | 宋体，小四 | 左对齐，“关键词：”加粗 |
| 一级标题 | 宋体，小三（15 pt），加粗 | 居中 |
| 二级标题 | 宋体，小四（12 pt），加粗 | 左对齐，不首行缩进 |
| 三级及更低级标题 | 宋体，小四（12 pt），加粗 | 左对齐，靠编号与缩进区分层级 |
| 模型、算法功能性小标题 | 宋体，小四（12 pt），加粗 | 左对齐，不首行缩进，写明名称与作用 |
| 正文 | 宋体，小四（12 pt） | 两端对齐，首行缩进 2 字符 |
| 图题、表题 | 宋体，五号 | 居中 |
| 表内文字 | 宋体，五号或小五 | 按列统一 |
| 参考文献 | 宋体，五号 | 悬挂缩进 |

正文推荐使用固定值 20 pt 或等效的约 1.5 倍行距，二者择一并全文统一；正文自然段默认段前、段后为 0，依靠首行缩进而非空行分段。全文段前段后、行距、编号和缩进必须统一。同级标题不得出现字号、粗细或缩进漂移。

### 4.4 标题层级与版面节奏

1. 论文题目只出现一次；一级标题使用“一、”，二级标题使用“1.1”，三级标题使用“1.1.1”，更低层级只在确有多个并列模型、算法或步骤时使用。
2. 一级标题居中，二级及以下标题左对齐；标题不首行缩进，不在末尾添加句号或冒号。模型、算法功能性小标题可用“名称——作用”结构，其中破折号后的文字必须说明其在本问中的职责。
3. 标题之间必须形成清楚而克制的大小关系：题目最大，一级标题次之，“摘要”居中单列，二级及以下标题与正文同为小四但全部加粗，并通过编号、左边距和段前距区分。
4. 推荐段前段后：一级标题 18 pt/12 pt，二级标题 12 pt/6 pt，三级标题及功能性小标题 6 pt/3 pt；同级标题使用完全相同的间距。
5. 标题必须与其后至少两行正文、公式或图表保持同页，不得孤悬页末；不得用连续空行、手工空格或不可见字符调整标题位置。
6. 原则上不为普通二级或三级标题强制分页。摘要、正文起始页、附录起始页仍按本规范的强制分页要求处理；其余分页以避免大块空白、图表拆散和公式断裂为准。

## 5. 标题、摘要与关键词

### 5.1 论文标题

1. 标题应体现研究对象，并优先体现正文真正起主导作用的核心模型或算法。
2. 宜控制在一行内，不得为追求短而丢失研究对象。
3. 可采用“基于 XXX 模型的 XXX 问题研究”“基于 XXX 模型与 XXX 方法的 XXX 研究”等形式。
4. 当研究对象足够明确时，可采用简洁问题型标题，不必机械使用“基于”。
5. 不得堆砌正文未重点使用的算法名称，不得使用“某问题研究”“数学模型分析”等空泛标题。

### 5.2 摘要页硬要求

1. 摘要专用页的组成和分页执行 `OFFICIAL-CUMCM-001`。
2. 摘要控制在一个版面内，使评审仅阅读第一页即可知道研究内容、逐问方法、关键结果和可信度。
3. 不得在摘要中引用图、表、公式或参考文献编号。
4. 不得写程序目录、软件与库版本、运行入口、文件路径、长公式推导或大段背景常识。

### 5.3 摘要固定逻辑

#### 第一段：总体概述

通常使用 2—3 句话、约 3—5 行，包含：

- 问题背景或研究意义；
- 总体建模主线；
- 主要模型或方法类别；
- 解决的核心问题或总体成果。

第一段不得展开详细求解过程，也不得无序罗列模型名称。

#### 各子问题摘要

每个子问题单独成段，依次说明：

1. 本问任务或数学类型；
2. 关键建模思路；
3. 核心模型或方法；
4. 必要的数据与求解方式；
5. 题目要求的关键结果；
6. 结果意义、检验或可信度。

计算型问题必须给出题目要求的核心数值与单位；开放型问题必须给出明确方案、排序、类别、策略或结论。不得只写“得到了较好结果”。

#### 最后一段：总结与升华

有实质内容时，可概括模型体系、主要优点、稳健性、局限、适用范围或推广价值；没有实质信息时可省略，不写空泛套话。

### 5.4 摘要加粗规则

摘要中的**核心模型、关键数值、最终方案和结论性短语必须加粗**。可同时加粗“针对问题一/二/三”等引导语，但不得整段加粗或大量加粗过程细节。

### 5.5 关键词

1. 一般为 4—6 个；
2. 优先覆盖研究对象、研究目的、核心模型、求解算法和验证方法；
3. 使用统一分隔符，推荐中文分号；
4. 不使用“数学建模”“问题分析”“MATLAB”等过宽词作为主要关键词；
5. 缩写作为关键词时，摘要中应已解释全称。

## 6. 正文章节写作要求

### 6.1 一、问题重述

#### 6.1.1 问题背景

- 用自己的语言概括真实背景、研究对象和应用意义；
- 删除故事化、宣传性和无关描述；
- 不提前展开模型、算法和结果；
- 原则上控制在 1—3 个自然段。

#### 6.1.2 问题要求

- 将题目各问转化为明确任务；
- 写清输入、条件、约束和输出；
- 对题目要求生成的附件、表格、预测文件等单独注明；
- 不得照抄原题，不得改变题意。

### 6.2 二、问题分析

第二章必须按子问题分别说明：

- 子问题的数学本质；
- 已知量、未知量和主要约束；
- 数据特征和核心困难；
- 与前后问题的关系；
- 拟采用的模型或方法；
- 选择该方法的理由；
- 预期输出和验证路径。

复杂题宜在章末设置总体技术路线或整体建模思路；需要图示时执行 `PW-FIG-001`，并确保其与后文章节和实际计算逻辑一致。

### 6.3 第五章各问的“建模准备”

“建模准备”位于每问“模型建立”之前，用于提供紧邻公式推导且不可缺少的预备条件。其职责按题型选取：

- 建立坐标系、时间基准、对象索引、几何关系或空间判定方法；
- 给出数据变换、归一化、特征构造、指标口径或中间量定义；
- 说明机理简化、状态划分、边界识别或关键预备公式；
- 交代从前问继承的变量、参数和结果，以及本问新增或改变的部分；
- 明确随后各局部模型的输入、输出与衔接顺序。

简单问题可用 3—8 行完成；复杂几何、物理机理或数据流程可配公式，并按 `PW-FIG-001` 使用必要图示适度展开，不设机械字数上限。第二章“问题分析”回答“本问难在哪里、为何选择该方法”，第五章“建模准备”回答“正式建模前具体准备什么”；两者不得互相复制，也不得以“前文已经分析”为由删除本节。

### 6.4 章节衔接与段落闭环

1. 各节开头说明本节目的及与上一节的关系；
2. 各节结尾给出本节得到的模型、参数、结论或下一步输入；
3. 重要图、表和公式采用“文字引入—对象呈现—结果解释”的闭环；
4. 不得在章节之间突然切换模型、数据口径或符号而无过渡；
5. “综上”“由此”“因此”等连接语必须对应真实推导关系。

### 6.5 三、模型假设

1. 原则上用纯文字编号列举，不放无关图表和复杂公式。
2. 数量按需要确定，常见为 4—7 条，但不得凑数。
3. 假设必须与模型直接相关，并说明物理、业务或统计合理性。
4. 不重复题目已明确给出的事实，不以假设直接消除核心难点。
5. 不写“题目数据真实可靠”“不考虑一切偶然因素”等空泛假设。
6. 对结果影响显著的假设，必须在误差、灵敏度或模型评价中回扣。
7. 数据驱动模型应区分业务假设、统计假设和数据处理规则。

### 6.6 四、符号说明

1. 必须使用三线表；
2. 原则上包含“符号、含义、单位”三列；
3. 凡符号没有单位，单位栏统一标为“—”，包括无量纲量、比值、概率、计数、判别准则和纯编号；不得用“1”代替“—”；
4. 同一符号全文含义唯一；
5. 集中列示高频核心符号，局部临时变量可在公式附近定义；
6. 向量、矩阵、集合、随机变量与标量的字体规则必须统一；
7. 不得把模型名、软件名和无需解释的常用数学符号大量塞入符号表。

## 7. 数据理解与预处理

题目含数据附件时，必须先完成数据审计，再开始模型训练、评价或优化。

### 7.1 数据审计内容

必须核对并在论文中呈现会影响建模与结论的部分：

- 数据来源、文件用途和关键字段；
- 字段类型、单位、样本量、时间范围和空间范围；
- 主键或对象标识；
- 缺失值、重复值、异常值和非法编码；
- 类别分布、数量级和主要统计特征；
- 处理前后样本量；
- 训练、验证、测试或时间切分方式；
- 数据泄漏风险及防范措施。

完整文件清单、脚本路径、随机种子归档和数据审计日志记录在工作区，不要求逐项写入正文。

### 7.2 预处理规则

1. 不得只写“进行了数据预处理”。
2. 删除、填补、截尾、平滑、标准化、编码和聚合必须说明规则和理由。
3. 不得无说明删除异常值；异常值可能代表真实极端状态时，应采用稳健方法或分情形分析。
4. 标准化、降维和特征选择原则上只在训练数据上拟合，再应用于验证/测试数据。
5. 时间序列不得随机打乱导致未来信息泄漏。
6. 同一对象的多条记录不得不当分散到训练集和测试集造成对象泄漏。
7. 所有处理必须与实际代码和结果一致。

### 7.3 可视化预处理

用于缺失、异常、离散程度、偏态、时间变化、类别不平衡、变量关系或空间分布的数据图，统一执行 `PW-FIG-001`；不得绕过其中的论证目标、数据剖析和证据要求。

## 8. 模型建立的强制写法

### 8.1 总原则：先解释，后数学化

每个子问题必须遵循：

```text
建模准备与关键问题转化
→ 数据处理或机理简化
→ 变量、参数和评价指标定义
→ 按“模型名称——作用”组织局部关系与组成公式
→ 完整模型集中汇总
→ 模型输出与题目要求对应
```

不得一进入模型建立就堆放目标函数、约束或大段公式。

### 8.2 问题转化与模型选择

必须说明：

1. 原问题如何抽象为数学问题；
2. 核心对象、主要矛盾和待求量；
3. 保留和忽略了哪些现实因素；
4. 本问属于优化、预测、评价、分类、微分方程、仿真或其它何种任务；
5. 为什么选择当前模型，候选方法为何不作为主模型；
6. 模型输入、输出与题目目标如何对应；
7. 与前面子问题的继承、修改或扩展关系。

建模与编码阶段的算法资源查阅、候选比较、主模型数量和库外方法偏离记录执行 `docs/standards/workspace-governance.md` 的 `WG-MODEL-001`。本节只要求论文解释与评审理解有关的模型选择理由，不重复工程记录字段。

### 8.3 变量、参数与指标

按实际需要定义决策变量、状态变量、输入输出变量、模型参数、中间变量、风险收益指标、随机变量、时间/空间/对象索引、单位、定义域和取值范围。

任何符号必须在首次使用前或首次使用处解释；高频符号与符号说明表一致。

### 8.4 局部关系与公式推导

应按模型逻辑分别建立收益、成本、风险、概率、损失、似然、评价指标、守恒关系、状态转移、控制方程、初边值条件及资源或业务约束。

每个局部公式出现前必须说明建立依据，出现后解释各项数学含义和实际意义。不得连续堆放多个公式而无文字说明。

### 8.5 局部模型的标题与作用

每个可独立命名的主模型、局部模型、机制模块或算法阶段都必须设置左对齐、加粗的功能性小标题；同一问包含多个时逐个设置，只有一个时也不得只用“问题一模型的建立”代替具体模型名。标题采用以下任一形式并全文统一：

```text
余弦效率模型——量化入射夹角造成的能量损失
路径规划模型（作用：生成满足容量与时窗约束的访问顺序）
```

具体要求：

1. 小标题必须同时给出可识别的模型名称和本模型在当前子问题中的作用，不得只写“模型一”“模型二”“计算模型”或算法缩写。
2. 小标题置于对应解释、图示和公式块的左上方，不首行缩进，并与其后内容保持同页；不得把模型名称埋在正文中、公式后或图题中。
3. 每个局部模型按“名称与作用—输入输出—必要图示—关系或公式—本模块输出及去向”组织；简单模块可合并说明，但不得省略名称与作用。
4. 局部模型是否需要图示以及图示的职责、类型、内容和质量统一执行 `PW-FIG-001`。
5. 同一问的局部模型小标题使用同一语法、字号、字重和左边距；模型名称在摘要、正文、图表和完整模型汇总中保持一致。

### 8.6 每问的完整模型汇总

完成局部推导后，每个子问题必须集中给出一次可独立阅读的完整模型，包括实际需要的：

- 目标函数或核心方程；
- `s.t.` 约束；
- 初始条件、边界条件和耦合条件；
- 变量范围、定义域或可行域；
- 参数条件；
- 输入与输出。

完整模型之后逐项说明目标、主要条件和输出如何回答题目。存在三个及以上局部模型或关系组时，宜用左大括号或对齐公式组集中列示，并在左侧用与功能性小标题一致的短语标出各组作用，使读者能由“模型名称—作用”直接定位到对应公式。除等价变形或求解需要外，汇总后不得新增未纳入汇总的核心关系。

### 8.7 优化模型

必须集中列出决策变量、目标函数、`s.t.` 约束、变量范围、多目标处理方法以及目标与约束的实际意义。

优化模型先列目标函数，下一行以正体 `s.t.` 集中列约束。当同一模型存在三条及以上并列约束时，使用左大括号统括并按主要关系符对齐：

```latex
\begin{aligned}
\min_{\boldsymbol{x}}\quad & f(\boldsymbol{x})\\
\mathrm{s.t.}\quad &
\left\{
\begin{aligned}
g_1(\boldsymbol{x}) &\le 0,\\
g_2(\boldsymbol{x}) &\le 0,\\
h_1(\boldsymbol{x}) &= 0,\\
\boldsymbol{x} &\in \Omega.
\end{aligned}
\right.
\end{aligned}
```

多目标模型必须说明加权和、层次优化、ε-约束、Pareto 前沿或其它方法的理由；不同量纲目标先无量纲化。权重不得无依据指定，关键权重应做稳定性或敏感性检查。

整数、离散或组合决策不得先求连续解后直接四舍五入作为最终答案。取整、修复或启发式后处理后，必须重新检查全部约束、目标值变化和方案可行性。

### 8.8 微分方程与物理模型

必须集中列出控制方程、初始条件、边界条件、界面或耦合条件、定义域、参数物理意义与单位及简化假设。从三维降至二维/一维、连续系统离散化或多层系统耦合时必须说明依据。

### 8.9 统计与机器学习模型

必须集中说明预测目标或标签、特征含义、数据划分、核心预测函数、损失/似然/学习准则、参数估计、超参数选择、评价指标、基准模型和防泄漏措施。

分类模型不得只给准确率；回归模型不得只给拟合曲线；聚类模型不得只给聚类图而无聚类数选择和解释。

### 8.10 评价模型

必须集中说明指标体系、指标方向、标准化、权重计算、综合评价函数、排序或分类规则、权重稳定性和指标冗余检查。每个指标必须解释“为什么影响评价对象”和“数值增大意味着什么”。

### 8.11 算法与仿真模型

必须集中说明输入输出、状态变量、核心规则或迭代公式、关键参数、初始状态、停止条件、重复仿真次数和结果汇总方式。只有当规模可行性影响方法选择或结论时，才讨论运行规模或算法复杂度；不得机械写时间复杂度、空间复杂度。

## 9. 模型求解与算法说明

每个子问题的模型求解必须说明：

1. 采用的求解方法、算法或求解器及必要选择依据；
2. 求解基本思路和关键步骤；
3. 对结果有实际影响的搜索范围、步长、网格、容差、样本量、超参数或停止条件；
4. 主要软件、求解器或计算工具名称；
5. 得到的关键数值、方案、预测、分类、评价或仿真结果；
6. 结果是否满足约束、量纲、边界条件和实际常识；
7. 论文中的步骤、公式、参数、图表与实际计算必须一致。

不得为满足形式而虚构迭代过程、搜索范围、随机种子或算法比较。解析求解、直接代入或简单代数计算可简要说明，无需机械拆分步骤。

### 9.1 方法选择与必要比较

当存在两种及以上真正可行的方法，且选择会显著影响精度、稳定性、计算效率、可解释性或可靠性时，应比较与本题有关的指标并说明选择依据。

无需机械比较全部复杂度指标。稳定性、收敛性、网格无关性及不同初值一致性只在相关方法适用且会影响结论时检查。

### 9.2 求解步骤

复杂算法或多阶段计算宜使用编号步骤，内容与实际过程一致，例如：

1. 准备输入数据或初始参数；
2. 完成必要预处理或变量计算；
3. 建立待求方程、目标函数或迭代关系；
4. 执行核心计算或调用求解器；
5. 检查收敛、约束和边界条件；
6. 输出并解释关键结果。

步骤数量按实际过程确定。采用正式算法块时，依次写“算法 x：名称——作用”“输入”“输出”和 `Step 1, Step 2, ...`；算法标题加粗左对齐，输入输出必须与模型定义及程序实际接口一致。算法流程图统一执行 `PW-FIG-001`。

### 9.3 正文与工作区的工程边界

正文只说明影响模型和结论的科学设置。以下内容默认记录在工作区，不写入论文正文：

- 操作系统、硬件、软件和依赖库的完整版本表；
- 环境安装命令、运行入口、命令行和目录树；
- 输入输出文件路径、日志位置、缓存和完整默认参数；
- 完整复现手册；
- 与题目无关的时间复杂度、空间复杂度和工程性能明细。

若某一版本差异、随机设置、硬件精度或规模限制会实质改变结果，必须在论文中说明其科学影响，而不是只给工程清单。

## 10. 结果呈现、分析与验证

### 10.1 每问最低要求（`PW-VAL-001`）

每个子问题必须：

1. 给出题目要求的主要结果；
2. 用文字直接回答本问；
3. 解释结果的实际含义；
4. 提供充分且适用的分析或验证；
5. 说明结果的适用条件或主要限制。

原则上，每问从结果分析、误差分析、模型检验、灵敏度分析或其它等效证据中选择至少两项；确有题型原因不适用时，必须用推导、证明、基准算例、边界检查、约束检查等补足论证，不得降低可信度。

### 10.2 可选分析与验证

- 结果分析；
- 误差或残差分析；
- 模型检验；
- 灵敏度和稳健性分析；
- 基准模型对比；
- 消融实验；
- 交叉验证；
- 收敛性或网格无关性分析；
- 守恒量检查；
- 极端情形或边界检查；
- 约束满足性检查；
- 现实案例、典型样本或抽样稳定性验证。

没有真实值时不得强行计算“误差率”；没有关键可扰动参数时不得机械做灵敏度分析；纯理论问题可用推导、证明或算例替代。

### 10.3 先给答案，再展开证据

每问的结果分析应先用一段话明确给出最终答案，再用表格、图形、指标、推导或案例解释依据。不得让评审阅读数页后仍无法确定结论。

结果表原则上包含对象编号或类别、核心输出、单位、必要误差或状态、最终决策或结论。正文展示代表性结果和关键汇总，超长明细放附录，并在正文指出位置。

### 10.4 结果可信度与结论强度

验证结论必须给出判据、过程、数值/图表/统计量、明确判断及仍存在的不确定性。

“准确、稳定、最优、显著、优于”等词必须有相应证据。禁止仅写“由图可知模型准确”“结果符合实际”“效果很好”。

### 10.5 典型案例与解释

适合时选取最优、最差、中间、边界、异常或不同类别代表样本，说明模型为何产生对应结果，以增强可解释性和实际可操作性。

### 10.6 结果可视化的清晰性与直观性

结果分析中的数据图、诊断图、验证图和多面板组合图全部执行 `PW-FIG-001`。该控制项未通过时，相关子问题不得视为完成结果呈现或验证。

## 11. 图片与表格

### 11.1 图片

论文图片的选择、位置、编号、图题、排版、格式和最终 PDF 视觉检查只以 `docs/standards/paper-figures.md` 的 `PW-FIG-001` 为准，本规范不维护第二套图片参数。

### 11.2 表格排版

1. 表题置于表上，统一为“表 x  标题”；
2. 表格优先使用三线表，不使用无意义竖线；
3. 表头写清变量或指标及单位；
4. 同列数值的小数位、有效数字和对齐方式统一；
5. 数值过多时展示代表行并用省略号说明，完整表放附录；
6. 不得把数据表截图插入；
7. 表后必须解释主要发现，而不是逐行朗读；
8. 跨页表必须重复表头，避免表题与表体分离；
9. 列宽应按内容分配，避免等宽导致长文本拥挤或短数值列浪费；
10. 单元格留有适当内边距，不使用会截断文字的固定行高。

## 12. 公式、符号、单位与有效数字

### 12.1 公式排版

1. 重要公式单独居中，编号右对齐；
2. 全文采用统一编号方式，可连续编号或按章编号；
3. 正文引用使用“式（x）”，不使用含义不清的“上式”“下式”；
4. 多行公式按等号或主要关系符对齐；
5. 一个完整公式组尽量不跨页；
6. 公式标点符合所在句子的语法；
7. 公式不得以图片或截图插入；
8. 公式前说明建立依据，公式后解释变量、条件和实际含义。

### 12.2 多条方程与条件的左大括号规则

1. 同一模型中存在三条及以上并列约束、控制方程、初边值条件、耦合条件、状态转移或分段规则时，使用左大括号统括；
2. 组内按等号、不等号或主要关系符纵向对齐；
3. `s.t.` 仅用于优化模型，置于约束组左侧并使用正体；
4. 微分方程、联立方程和分段关系只使用大括号，不机械添加 `s.t.`；
5. 一条或两条简单关系可直接对齐；
6. 公式组过长时按物理含义或约束类别拆分并说明各组作用；
7. 一个完整公式组原则上使用一个编号，需要独立引用内部条件时使用子编号；
8. 不得为追求大括号形式把不同模型强行合并。

### 12.3 正斜体规则

1. 标量变量、参数、未知量、一般函数自变量、表示数学量的拉丁字母和希腊字母使用 Times 系列斜体；
2. 向量、矩阵使用统一的 Times 系列粗斜体或粗体；
3. 下标为变量索引时用斜体，下标为英文缩写、中文说明或固定含义时用正体；
4. `sin`、`cos`、`ln`、`exp`、`max`、`min`、`argmin`、`argmax`、`s.t.`、微分符号、单位和转置符号使用正体；
5. 数字使用 Times New Roman 正体；
6. 公式中的中文说明使用宋体；
7. 不得在同一论文中混用多套数学字体。

### 12.4 单位与量纲

1. 重要变量首次出现时给出单位；
2. 表头和坐标轴必须标单位；
3. 单位使用规范符号，不随意中英文混写；
4. 同一物理量全文采用统一单位；
5. 公式相加减项必须量纲一致；
6. 不同量纲项组成目标函数时，必须说明归一化或尺度处理。

### 12.5 有效数字

1. 结果精度由原始数据精度、模型误差和实际应用共同决定；
2. 不得输出虚假高精度；
3. 同类结果采用统一小数位；
4. 整数型决策不得保留无意义小数；
5. 百分数与小数表达全文统一；
6. 区分“百分比变化”和“百分点变化”；
7. 摘要、正文、图表、附录和代码输出的数值、单位和舍入必须一致。

## 13. 模型评价、改进与推广

### 13.1 模型优点

必须结合实际证据说明，可从机理解释性、数据适应性、稳定性、精度、求解效率、特殊结构利用、决策可操作性、稳健性或规模扩展性中选择。每个优点应指出对应模型结构、实验结果或检验证据。

### 13.2 模型缺点

如实说明假设限制、数据限制、参数依赖、未考虑因素、局部最优风险、泛化能力、数值误差和实际应用条件。不得把缺点写成推翻全部论文的致命错误，也不得回避真实局限。

### 13.3 模型改进与推广

必须说明：

- 可推广到哪些对象、地区、行业或尺度；
- 推广时哪些变量、约束和参数需调整；
- 需要补充什么数据；
- 如何扩展到动态、多目标、随机或鲁棒场景；
- 推广后的验证方式。

不得只写“模型具有良好的推广性”。

## 14. 参考文献与引用

### 14.1 数量与组成（`PW-CITE-001`）

参考文献原则上不少于 **6 篇**。以下两本基础教材必须列入参考文献，并在正文介绍相应建模方法、算法或通用理论时实际引用：

```text
[1] 姜启源, 谢金星, 叶俊. 数学模型（第五版）[M]. 北京: 高等教育出版社, 2018.
[2] 司守奎. 数学建模算法与应用[M]. 北京: 国防工业出版社, 2011.
```

其余至少 **4 篇**应与题目背景、核心模型、算法、参数来源或验证方法直接相关。

这是本工作区的论文质量门禁，不冒充全国组委会统一规定。不得为了满足数量加入无关文献；若未能检索、核验并实际使用足够文献，应阻止发布而不是虚构或凑数。

### 14.2 文献质量

1. 所有文献必须真实、可检索并已实际打开核验；
2. 正文引用与文后编号一一对应；
3. 不得加入正文未引用的文献；
4. 专业背景、关键参数和算法优先引用原始论文、权威教材、标准、官方文档或高质量综述；
5. 不得用搜索结果摘要、不可靠网页或二手博客支撑关键专业依据；
6. 引用算法时优先引用原始或权威来源；
7. 文献格式全文统一；
8. 在线数据和网页资料写明足够的来源信息及访问日期。

### 14.3 正文引用

- 引用放在对应事实、方法、公式或参数附近；
- 不在段末堆放多个无法判断对应关系的文献编号；
- 自行推导的公式不伪装成文献结论；
- 两本指定教材必须在正文实际方法介绍处引用，不能只出现在文末；
- 所有公开来源、数据集、他人成果和按官方要求披露的 AI 工具均应规范标注。

文献检索过程、DOI/URL 核验和文献台账记录在工作区；论文呈现规范的正文引用和参考文献表。

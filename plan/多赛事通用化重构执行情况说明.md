# 多赛事通用化重构 · 执行情况说明

> 执行对象：`plan/mathematical-modeling-workspace_多赛事通用化重构方案.md`
>
> 执行范围：通用内核改造 + CUMCM 迁入 profile（plan 的机器层与 CUMCM 侧各阶段）+ MCM/ICM profile 接入（plan Phase 8–9 的赛事内容，2026-09-26 在 `feature/mcm-icm-profile` 分支完成，见第六节）。

## 一、总体结论

工作区已从「CUMCM 专用」改造为「通用数学建模内核 + 赛事 Profile」结构。当前仓库有 CUMCM 与 MCM/ICM 两个 profile；新增赛事时**只需新增 profile 目录，不改动任何内核代码、Core 文档或 Skill**（唯一例外是带口径冲突的键，见第六节的页数键下沉）。

回归判据全部满足：

- 四个测试文件 20 个用例全绿（含全链路 smoke）；
- `load_workspace_contracts` 对 CUMCM 的返回值与改造前**逐键 diff 为空**（46 键，数值与类型完全一致）；
- `check-workspace-layout.py` 对仓库根 PASS；
- 初始化器对未知赛事明确报错并列出可用赛事。

## 二、落地架构

### 三层职责

```text
Core（docs/ + tools/ + 通用模板）
    通用工作流、数据复现、证据、sandbox、产物导航；不含任何赛事字样
        ↓
Contest Profile（config/contests/<profile>/）
    赛事官方规则快照、机器契约键、论文框架引用；赛事规则唯一权威
        ↓
Project（workspace/projects/<contest>-<year>-<problem>/）
    00-admin/project.yaml 写入 contest 与 profile，只引用不重复定义
```

### 新的 profile 目录结构

```text
config/contests/cumcm/
├── profile.yaml    # 声明服务的赛事标识、契约键、论文框架路径
└── rules.md        # 原 docs/standards/cumcm-current-rules.md 整体迁入（含 OFFICIAL-CUMCM-001）

resources/templates/contests/cumcm/
└── paper-framework.tex   # 原 resources/templates/cumcm-paper-framework.tex 迁入
```

`profile.yaml` 三个字段：

- `contests`：该 profile 服务的赛事标识列表（解析 `--contest` 与 `project.yaml` 用，支持多赛事共用 profile，如未来的 `mcm`/`icm` 共用 `mcm-icm`）；
- `contract_keys`：该 profile 在 `rules.md` 机器契约块中提供的键（当前仅 `paper_maximum_bytes`），加载器据此做闭集校验；
- `paper_framework`：论文框架模板路径（相对 `resources/templates/`）。

### 机器契约两段加载（tools/control_contracts.py）

- 原 `DOCUMENTS`（9 个文件）拆为 `CORE_DOCUMENTS`（8 个）+ profile 文档集；
- 原 `REQUIRED_KEYS` 拆为 `CORE_REQUIRED_KEYS`（45 键）+ profile 键（由 profile.yaml 声明）；
- 无 `contest` 参数：只加载 Core 契约（workspace 级调用，如 `trace-artifact-impact.py`、smoke 测试），不设默认赛事；
- 带 `contest` 参数：解析 profile，合并其契约键；profile 不得重定义 Core 键，实际键集必须与 `profile.yaml` 声明一致；
- `resolve_profile()` / `available_contests()` 提供赛事→profile 解析与报错信息。

### 赛事身份与解析链

- 初始化器 `init_modeling_project.py`：`--contest` 必填（不再默认 cumcm），解析失败即报错并列出可用赛事；生成的 `project.yaml` 同时写入 `contest` 与 `profile` 两个字段；
- 审校脚本 `audit_modeling_project.py`：从被审项目的 `00-admin/project.yaml` 读取 `contest`，按 profile 加载契约（含 `paper_maximum_bytes` 体积门禁）。

## 四、与方案的偏差（小环节自行决定项）

| 偏差 | 理由 |
|---|---|
| `--contest` 从默认 `cumcm` 改为必填 | 方案要求 workspace 级调用「不设默认赛事」；必填参数是最直接的落实 |

## 五、日后新增一个赛事的操作

以假想的 `mcm-icm` 为例，只需三步（该示例已按第六节实际落地）：

1. 新建 `config/contests/mcm-icm/profile.yaml`（声明 `contests: [mcm, icm]`、契约键、论文框架）和 `rules.md`（当届官方规则快照 + 机器契约块）；
2. 新建 `resources/templates/contests/mcm-icm/paper-framework.tex`；
3. 初始化：`init_modeling_project.py --contest mcm --year 2027 --problem a`。

不需要改：`control_contracts.py`、两个 Skill、任何 Core 文档、任何测试。Core 文档若需引用赛事规则，一律用中性锚点「当前项目赛事 profile 的官方基线」。

注意：新增 profile 的契约键（如美赛的页数口径键）需要在 profile 的 `rules.md` 机器契约块中定义并列入 `profile.yaml` 的 `contract_keys`；Core 键的结构与含义不变。页数等带口径的规则在迁移美赛时必须同时表达统计口径（含不含 Summary Sheet 等），不能只换数字。（该注意事项在第六节落地时触发了一次必要的内核调整。）

## 六、MCM/ICM profile 接入（2026-09-26，`feature/mcm-icm-profile` 分支）

### 6.1 内核调整：页数口径键下沉到 profile

美赛官方规则为**全提交 ≤ 25 页**（含 Summary Sheet、目录、参考文献、附录与代码，仅 “Report on Use of AI” 一节不计），与 Core 的 `body_page_minimum = 20` / `body_page_maximum = 30`（CUMCM 正文口径，摘要页和附录不计）冲突：合规美赛论文会在 20 页下限上被误判阻断。经用户选定方案，把页数口径键从 Core 下沉到 profile：

- `tools/control_contracts.py`：`body_page_minimum`、`body_page_maximum` 移出 `CORE_REQUIRED_KEYS`（45→43 键），校验规则不变，由各 profile 的 `contract_keys` 声明并提供；
- `docs/standards/paper-quality-audit.md`：契约块移除这两个键；§4.3 的 20—30 页口径改为「页数上下限与统计口径由当前项目赛事 profile 的契约键与其官方基线共同定义」；
- `cumcm` profile：`rules.md` 机器契约新增 `body_page_minimum = 20`、`body_page_maximum = 30`，并注明这是工作区内部质量门禁而非官方规则，统计口径为摘要专用页与附录不计；
- `mcm-icm` profile：`body_page_maximum = 25`（全提交口径，仅不含 AI 使用报告一节），不设官方或内部页数下限；
- 审校脚本 `audit_modeling_project.py`：`body_page_count` 门禁改为 `getattr` 取值，允许 profile 只设上限不设下限（报错信息相应支持 `<= N` 形式）；
- 回归：cumcm 的契约返回值除页数键改由 profile 提供外数值不变（20/30、20,000,000 字节均与下沉前一致），20 个测试全绿（1 个测试因 Core-only 加载方式改为带 `contest="cumcm"` 加载），布局检查 PASS。

### 6.2 MCM/ICM profile 内容

- `config/contests/mcm-icm/profile.yaml`：`contests: [mcm, icm]`，契约键 `paper_maximum_bytes` + `body_page_maximum`，论文框架路径 `contests/mcm-icm/paper-framework.tex`；
- `config/contests/mcm-icm/rules.md`（control_id `OFFICIAL-MCM-ICM-001`，last_verified 2026-09-26，对准 2027 届官方 Instructions）：25 页全提交口径与例外（AI 报告不计页）、Summary Sheet 第 1 页、每页页眉含控制号与页码、单个 PDF/英文/≥12 pt、附件 <25 MB（按十进制 25,000,000 字节从严）、控制号命名与严格匿名、AI 使用须行内引用 + 参考列表 + “Report on Use of AI” 附加节。

### 6.3 论文框架模板

`resources/templates/contests/mcm-icm/paper-framework.tex`：以开源 mcmthesis（LPPL 1.3c，latexstudio / Liam Huang）的页面与页眉实现为参照，重写为符合工作区约定的可复用模板（`TemplateField` 占位、`safeincludegraphics` 缺图阻断、`includecode` 缺码阻断、控制编号引用）。与 cumcm 框架的结构差异均来自官方规则差异：Summary Sheet 置于第 1 页并计入页数、页眉 `Team # <控制号> Page N of M`、目录计入页数、无支撑材料清单（官方不接收程序文件，代码直接排印于计入页数的附录）、参考文献含 AI 工具条目、文末 “Report on Use of AI” 不计页数。已用 xelatex 三轮编译验证（11 页，无错误、无未定义引用），并经 `--contest icm` 全链路初始化冒烟验证框架复制正确。

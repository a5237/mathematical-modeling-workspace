- 初始化器对未知赛事明确报错并列出可用赛事。

## 二、落地架构

### 三层职责

```text
Core（docs/ + tools/ + 通用模板）
    通用工作流、数据复现、证据、sandbox、产物导航；不含任何赛事字样
        ↓
Contest Profile（config/contests/<profile>/）
    赛事官方规则快照、机器契约键、论文框架引用；赛事规则唯一权威
        ↓
Project（workspace/projects/<contest>-<year>-<problem>/）
    00-admin/project.yaml 写入 contest 与 profile，只引用不重复定义
```

### 新的 profile 目录结构

```text
config/contests/cumcm/
├── profile.yaml    # 声明服务的赛事标识、契约键、论文框架路径
└── rules.md        # 原 docs/standards/cumcm-current-rules.md 整体迁入（含 OFFICIAL-CUMCM-001）

resources/templates/contests/cumcm/
└── paper-framework.tex   # 原 resources/templates/cumcm-paper-framework.tex 迁入
```

`profile.yaml` 三个字段：

- `contests`：该 profile 服务的赛事标识列表（解析 `--contest` 与 `project.yaml` 用，支持多赛事共用 profile，如未来的 `mcm`/`icm` 共用 `mcm-icm`）；
- `contract_keys`：该 profile 在 `rules.md` 机器契约块中提供的键（当前仅 `paper_maximum_bytes`），加载器据此做闭集校验；
- `paper_framework`：论文框架模板路径（相对 `resources/templates/`）。

### 机器契约两段加载（tools/control_contracts.py）

- 原 `DOCUMENTS`（9 个文件）拆为 `CORE_DOCUMENTS`（8 个）+ profile 文档集；
- 原 `REQUIRED_KEYS` 拆为 `CORE_REQUIRED_KEYS`（45 键）+ profile 键（由 profile.yaml 声明）；
- 无 `contest` 参数：只加载 Core 契约（workspace 级调用，如 `trace-artifact-impact.py`、smoke 测试），不设默认赛事；
- 带 `contest` 参数：解析 profile，合并其契约键；profile 不得重定义 Core 键，实际键集必须与 `profile.yaml` 声明一致；
- `resolve_profile()` / `available_contests()` 提供赛事→profile 解析与报错信息。

### 赛事身份与解析链

- 初始化器 `init_modeling_project.py`：`--contest` 必填（不再默认 cumcm），解析失败即报错并列出可用赛事；生成的 `project.yaml` 同时写入 `contest` 与 `profile` 两个字段；
- 审校脚本 `audit_modeling_project.py`：从被审项目的 `00-admin/project.yaml` 读取 `contest`，按 profile 加载契约（含 `paper_maximum_bytes` 体积门禁）。

## 四、与方案的偏差（小环节自行决定项）

| 偏差 | 理由 |
|---|---|
| `--contest` 从默认 `cumcm` 改为必填 | 方案要求 workspace 级调用「不设默认赛事」；必填参数是最直接的落实 |
| smoke 测试 `--contest smoke` 改为 `cumcm` | profile 化后非真实赛事无法解析；测试意图是全链路而非赛事无关性，`cumcm` 即真实路径 |
| `project.yaml` 同时写 `contest` 与 `profile` | 方案 2.1 的设计；`contest` 拼项目 ID，`profile` 定位规则目录，二者可不同 |
| contest→profile 映射放在 `profile.yaml` 的 `contests` 列表 | 方案未定落点；声明式反查避免在初始化器里写死映射表 |
| MCM/ICM 相关阶段未执行 | 用户决定：先改造成可扩展模式，美赛内容日后加入 |

## 五、日后新增一个赛事的操作

以假想的 `mcm-icm` 为例，只需三步：

1. 新建 `config/contests/mcm-icm/profile.yaml`（声明 `contests: [mcm, icm]`、契约键、论文框架）和 `rules.md`（当届官方规则快照 + 机器契约块）；
2. 新建 `resources/templates/contests/mcm-icm/paper-framework.tex`；
3. 初始化：`init_modeling_project.py --contest mcm --year 2027 --problem a`。

不需要改：`control_contracts.py`、两个 Skill、任何 Core 文档、任何测试。Core 文档若需引用赛事规则，一律用中性锚点「当前项目赛事 profile 的官方基线」。

注意：新增 profile 的契约键（如美赛的页数口径键）需要在 profile 的 `rules.md` 机器契约块中定义并列入 `profile.yaml` 的 `contract_keys`；Core 键的结构与含义不变。页数等带口径的规则在迁移美赛时必须同时表达统计口径（含不含 Summary Sheet 等），不能只换数字。
